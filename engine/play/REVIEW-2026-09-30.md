# PS2 core review and Claude handoff

## Follow-up: Mirra loading and THPS4 pacing

Core `30b2881fcbc9` includes patches `0027` through `0030` and is deployed to Unraid at the user's request. The live app references this version, its served wasm SHA-256 matches the tested local binary (`093116ba1a9da0546d8b6588492029552af0dda53c96f80e83c1d271f508f971`), and the isolation headers are present. Deployment and verification logs: `work/deploy-mirra-thps.log`, `work/verify-mirra-deploy.log`. Previous image retained as `webstationx:before-mirra-thps-fixes`. This follow-up supersedes the Mirra loading limitation below; the original review remains as historical evidence.

- **Mirra root cause:** a blocked `CdSync` call returned without rechecking whether the drive was still idle. With the audio thread (priority 29) and level loader (priority 122) waiting, the audio thread could start another read before the loader resumed. The loader's next `CdRead` was rejected as busy; it interpreted stale bytes as ISO directory data, generated impossible sector addresses and corrupted its saved registers. The fix re-enters the import stub after waking, preserves both blocking sync modes, and requests rescheduling when releasing waiters. It preserves busy-read rejection and does not special-case the game. This follows the wait/recheck behavior in the original disc's driver and the [PS2SDK implementation](https://github.com/ps2dev/ps2sdk/blob/master/iop/cdvd/cdvdman/src/cdvdman.c).
- **Mirra evidence:** the old core reproduces the stall from `mirra-preload.st`. The fixed core loads Woodward Camp with threading off, and a 120-second fresh boot with async threading at 2x reaches riding gameplay. The final ten samples average 56.1 delivered fps. Screenshots and logs are in `work/mirra-fixed-boot`; the gameplay state is `work/ps2-bench-states/mirra-fixed-gameplay.st`. Cold compilation still produces loading hitches; this is not a claim that all rendering or performance issues are solved. Already-corrupted suspended states require **Start from the disc**.
- **THPS4 pacing:** the previous limiter carried up to four frames of time debt, then rushed frames to catch up. The regression test fails on the old code with a 35 ms hitch followed by a 0.00 ms frame. The fix rebases after a missed deadline, including overruns inside the limiter, while retaining sub-ms clock tolerance. Tests cover 35/55/70/110 ms hitches, idle-work overruns, late frames, fast frames and uncapped mode.
- **THPS4 evidence:** 60-second Foundry replays at 2x with async threading complete on both cores. In the last 30 seconds, VM frames shorter than 10 ms decrease from 29 to 0; the fixed run ends at 59.4 delivered fps over ten samples. The runs used wall time and cold JIT caches, so their overall FPS difference is not a controlled throughput claim. This fixes a verified contributor to rubber-banding; it does not establish that every hitch on the friend's machine is gone. Results: `work/thps-pacing-before` and `work/thps-pacing-after`.
- **Threaded saves:** the fresh-boot app test exposed a second Mirra freeze after loading a gameplay save. Draining a worker can leave it parked on an interrupt with accepted DMA bytes still queued; those bytes and queued calls were absent from the state. Patch 0029 transfers pending interrupts into serialized device state and clears stale interrupts on discard. Patch 0030 captures only after queues are empty, advancing the normal VM loop while a save is pending (including when paused). It fails after five seconds if no safe boundary is reached, and cancels pending saves on reset/load/shutdown. Existing incomplete states are not repaired. The gameplay lifecycle regression passes in `work/mirra-save-boundary-app`: 59.0 fps before save, about 60 after load and after suspend/continue. Fresh boot with the disc fix reaches gameplay at 59.1 fps over the final 30 samples in `work/mirra-irq-app`; that earlier run documents the save failure before 0030.
- App production build, PS2 unit checks and audio resampling tests pass. THPS4's final-core Foundry gameplay check passes audio/card round-trip, save/load and suspend/continue (`work/thps-final-lifecycle`). `tools/ps2-test.mjs` now accepts `--min-fps` so a successful boot cannot hide a later loading freeze, measures elapsed time between picture samples, and waits for a confirmed load instead of clicking through an animating dialog. `--state-file` starts the same lifecycle check in gameplay.

## Completed fixes

- **Invalid generated wasm (crash):** CodeGen assumed every local count occupied one byte. Counts of 128 or more made the declared function body too short. Patch `codegen/0005` uses the actual LEB128 size. The new test builds real modules at 0, 1, 127, 128, 255, 16383 and 16384 locals across integer, float and SIMD types and asks V8 to compile them.
- **GS copies / corrupt command data:** finished Claude's trial GS copy implementation, removed temporary tracing, and exported it as `play/0025`. The game copies rendered color/depth values into differently formatted GS memory and reads them back as commands. The copy now uses the destination's pixel layout and converts drawn alpha back to GS representation. The existing whole-frame GL shortcut is now restricted to matching formats, full extents and different buffers, with scissor/cache state handled explicitly. This allows the tested ATV race to continue, but does **not** fix all its rendering: terrain and texture-atlas artifacts remain.
- **Limiter-induced slowdown:** previously, falling several frames behind reset the deadline to `now`, then added and slept another full frame. `play/0026` discards the debt without adding a delay. Its test simulates repeated 85 ms frames and separately verifies that fast frames remain limited.
- **Repeated VIF polling overhead:** once a drain establishes that the vector worker is stopped, reuse that synchronization until new work, a kick, a synchronous operation or a discard invalidates it. Previously repeated reads spun, locked and sampled clocks millions of times while nothing could change. Also retry queued VIF work after a running VU program finishes, even if that pass consumed no additional input bytes.
- **Misleading FPS tests:** both the bench and app test now count pictures actually delivered to the page. Core frame ticks continued reporting 60 during a reproduced Dave Mirra loading freeze. `probe.mjs --min-fps N` can enforce an ending picture-rate threshold; omit it for intentionally paused fingerprint tests.
- **Automatic settings:** an RTX 4060 Ti no longer counts as a higher GPU tier simply because 4060 is greater than 2070. Auto is capped at 2x; manual Ultra and explicit resolution overrides remain available. Manual presets no longer inherit an old automatic CPU underclock. Tuning ignores substantial disc/JIT stalls and does not treat vector-thread waiting as proof of EE CPU overload.
- **Useful slowdown reports:** read the core's existing VPU1 wait field, acquire shared frame counters atomically, and include frame rate, p95 frame time, JIT/disc/GS/vector waits and detected hardware in diagnostic reports. Sustained slow emulation sends one report per session without interrupting play.
- **Disc streaming stability:** validate byte ranges and block lengths before supplying/caching data; reject a server/proxy that ignores Range before buffering a multi-GB response; abort fetches and retry waits when leaving a game. HEAD requests now have a timeout.
- **Audio:** size the cushion in source samples when output sample rate differs, prevent downsampling past the producer, and reset interpolation/playback state after a ring reset. Tests cover five output rates from 11.025 to 96 kHz.

## Still unresolved

1. **ATV is still below playable full speed and has rendering corruption.** Removing unnecessary waits helps but does not solve the entire workload. A 120-second 2x run from `atv2-preload.st` exercises the race transition in `work/review-atv-final-long`; its last 60 seconds average 21.6 delivered fps. Both the baseline 1x screenshot (`review-atv-base/t045.png`) and final 2x screenshot (`review-atv-final-long/t090.png`) show corrupted terrain and a font atlas on the ground. These artifacts are not established to be caused by scaling or the new timing changes. Profile and optimize the actual race, not its 60 fps menus. Test against a fixed emulated-frame workload and collect the friend's browser/CPU and diagnostic record before attributing their result to the GPU.
2. **Dave Mirra stalls loading Woodward Camp.** Fresh-boot reproduction: Enter at 15/22 seconds, Cross (`KeyZ` in the bench) at 30/38/46/54/62 seconds. Reproduced with async threading and with threading off. Actual pictures stop while vblanks continue; single-thread profiling found the EE at the HLE idle-thread loop `0x1fc03108`, and GS idle. This is not demonstrated to be a vector-thread race or insufficient GPU throughput. `mirra-preload.st` preserves the level selection; `mirra-review.st` and `mirra-review-later.st` preserve successive stalled states. Module `0x45` RPC 4 is loading `ASSETS\\LEVELS\\WOODWARD\\WOODWARD.TXR;1`. IOP thread 8 moves from CD-sync wait in the game's directory parser at `0x5f010` to a runnable state with saved PC zero and corrupted saved registers/return address. Its directory search variables at `0x85bc0/0x85bc4` already contain implausible sector/count values in the earlier snapshot. The pending CD read completes; a permanently pending read alone does not explain the stall. Trace backward to the first bad write/search result before changing HLE scheduling. These are investigation leads, not an established root cause.
3. **Async emulation has weaker correctness guarantees.** Matching synchronous fingerprints does not prove async ordering for every game. Preserve the thread-off control case and repeat long gameplay/save-state tests when changing queues or GPU timing. No unproven sampler-object optimization was restored.
4. **GS readback remains costly and format-limited.** Color/depth readback synchronizes with the GPU. The new GL readback helper covers 32/24-bit color/depth without multisampling; other representations can still fall back to GS RAM. Full PS2 depth/alpha precision cannot be established by the ATV screenshot alone.

## Experiments rejected

- Expanding generic idle-loop detection to ANDI/64-bit loads did not materially improve ATV; reverted.
- Longer consumer spins / keeping the vector worker spinning briefly between submissions did not help; the latter made ATV materially slower. Reverted.
- Halving the emulated EE clock did not make ATV smooth. No per-game underclock was forced.
